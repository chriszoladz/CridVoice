User guide

Installation

Run the .exe installer for a current-user installation. Administrator access is not normally required. The installer checks Microsoft WebView2, which is normally included in Windows 11. Do not remove the packaged Python or service folders.

For the portable build, extract the complete ZIP to a writable folder, such as a folder inside your user directory. Start CridVoice.exe. Keep portable.flag, python/, service/, and model-catalog.json beside it. Do not run inside the ZIP or move the executable alone. Portable data is stored in data/ beside the executable. API keys use Windows Credential Manager on that computer.

First-run setup

  1. In AI processing, choose Managed local AI, Local server, or Connect a provider. The first option manages local inference; the second connects an existing local server; the third connects a selected cloud API. Every option remains available later.
  2. For an external provider, enter its base URL, API format, and optional API key, then choose Fetch models to request model IDs from that endpoint. Select the text model and, when appropriate, speech model. Lists do not identify capabilities: the provider must support the selected endpoint/model. Use Enter a custom model ID if discovery is unavailable or your intended ID is absent. Local servers often omit authentication. Anthropic format is for text; speech needs a separate compatible audio endpoint or local transcription.
  3. In Speech recognition, choose the speech engine, device, model, and language. English/Polish automatic detection is the default. A local text server can be combined with app-managed local speech.
  4. In Preferences, select the cleanup engine and its device/provider independently, then review context, transcript history, live preview, writing style, and startup preferences. Off · raw transcript requires no cleanup model/runtime.
  5. In Install components, review the hold shortcut and complete required local components list. On the default managed RTX 5070 Ti route this contains Whisper Turbo, NVIDIA speech runtime, Whisper Tiny for enabled live preview, Qwen3 4B, and llama.cpp GPU runtime. The total missing download size is displayed before starting.
  6. Choose Install required components & finish. The wizard automatically awaits each missing component, showing per-component and overall progress plus verification/extraction stages. Already-installed components are skipped and reused. Downloading 100% is not completion until verification/extraction succeeds.
  7. Use Pause setup if needed, then Resume setup. A failed step keeps the wizard open with Retry setup, preserving usable partial files and completed components. The wizard finishes only after fresh installed-state checks and the native readiness check succeed. A route using providers for both stages needs no local assets and can choose Finish setup directly.

An installed app with missing selected local components opens setup repair at the final component list. The incomplete callout and Test dictation also lead to repair, rather than starting a take that needs missing models. Settings → Run setup wizard lets you revisit any route. Repair preserves existing provider IDs, separate speech/cleanup selections, saved keys, and other settings. Leave a saved key blank to keep it. Close repair only while it is idle, or pause first.

Use Local models for later optional model changes/removal and live in-memory status. Use AI providers to add or test connections and Settings to choose which connection each stage uses. Browser preview cannot install or prove local readiness and cannot finish a local setup; fully provider-based preview settings remain available.

Navigation and status

The custom top bar replaces the Windows caption. Drag its text area to move the window, or double-click it to maximize or restore. The right-side controls minimize, maximize/restore, and close to the tray. Quit CridVoice in the tray menu exits the app. Help and window buttons are excluded from dragging.

Dialogs dim the whole window, including the header and logo. Tab and Shift + Tab cycle within the active dialog, including after an action becomes disabled or a toast is dismissed. Shared dialogs close with Escape, their Close control, or a click outside, then restore prior focus where available. A header click behind a shared dialog dismisses it without also operating the window. Close the dialog before using the header controls. Ctrl + K does not open Find a page over another active dialog. Setup retains its own mandatory/busy, pause, close, and Escape rules.

The sidebar groups Overview, History, Vocabulary, and Writing styles under Dictation. AI providers, Local models, Appearance, and Settings are grouped under Configuration. Use Find a page or Ctrl + K to search these pages, including keywords such as microphone, hotkey, clipboard, and retention. The expanded footer shows About CridVoice, the actual app version, and whether it is Installed or Portable. Settings has section jumps for its longer page.

Use Collapse sidebar in the top bar to give the main page more width while keeping a compact icon rail. Hover over an icon or focus it with the keyboard to see its page name, then select it to navigate. Expand sidebar restores the labels. The app remembers that choice, and Ctrl + K still opens page search while collapsed. At the default 1200×820 window and text size, idle Overview fits without page scrolling, including up to three recent entries. At 900×640, with a longer result, or with enlarged text, content can still scroll using the themed scrollbar.

Navigation icons stay in place when the sidebar expands or collapses. Sidebar width changes horizontally while labels fade; with a reduced-motion preference, the change is instant. Select either the full or compact logo to return to Overview. Its balanced Home control has visible keyboard focus and a brief activation pulse; reduced motion skips the pulse.

Overview shows plain dictation states such as Ready, Recording, Transcribing, Cleaning, Inserting, and Setup required beside the recording controls. The top bar shows whether settings are saved locally and whether each processing stage uses a local engine or a provider. Installed, Selected, Loading, and Loaded remain separate model states. The supplied waveform logo uses matching artwork for light and dark surfaces. The compact layout and custom title bar preserve shortcuts, downloads, and processing behavior.

Customize shortcuts

In Settings, choose Change beside Hold to dictate, Toggle dictation, or Rewrite selected text. Press the desired chord together, then release every key. Review the captured shortcut and choose Save; capture alone does not change settings. Conflicting or unsupported chords cannot be saved. Try again starts a new capture, while Cancel or Escape leaves the saved binding unchanged. An incomplete capture stops after 30 seconds; it does not start dictation. Release held keys before trying again.

The reset action restores that binding's default, subject to conflict validation. Defaults remain Ctrl + Windows for hold, Ctrl + Shift + Space for toggle, and Ctrl + Alt + R for rewrite. Escape is reserved for cancellation in the recorder. Other applications can still own the same chord, so avoid duplicate bindings across dictation tools.

Dictation

The header's processing button shows whether speech and text cleanup use local models or configured providers. Hover or focus it for the separate routes; click it to open the speech-processing settings. The adjacent save indicator reports settings saves. Model loading/readiness remains visible on Overview and Local models.

Installed selected local models warm in the background after launch. Overview shows their live readiness, and Local models offers Load selected models or Retry model loading. You can begin recording while they prepare; processing may still wait if warm-up has not finished. Explicitly unloading models cancels pending warm-up and releases the engines until you load or use them again, change the selected local route, or restart the app. Completed downloads alone do not undo explicit unloading. External providers remain under their own control and are not contacted by this preparation.

In the default Text output mode, place your cursor in the target text field. Hold Ctrl + Windows, speak naturally, and release both keys. The app captures only while recording, transcribes your audio, performs selected text cleanup, and inserts the result. Keep the field focused until insertion finishes. Technical modes can instead open the result for review as described below.

Either left/right Ctrl and Windows keys can be used. Release both keys between takes. Holding Windows while repeatedly tapping Ctrl is not a supported way to restart a take; release Windows and press the full chord again. Windows-key events involved in the hold chord are suppressed to avoid opening Start. Check conflicts with Wispr or any other tool registering the same shortcut; run one owner of the chord at a time.

Default insertion uses clipboard paste with restoration, supporting paragraphs without simulating Enter. If an existing format cannot be safely preserved before clipboard changes or input begin, CridVoice automatically uses Unicode typing and leaves the clipboard untouched. Settings also offers Unicode typing as the primary method. Busy-clipboard, paste, or restoration failures do not trigger a second insertion attempt; the output remains in Latest result and in History when history is enabled. New clipboard contents created during paste are preserved instead of overwritten by restoration.

For a partial-input error, check the target field before copying the full result. CridVoice stops further input rather than retrying a possibly incomplete insertion.

To keep a copy ready for manual paste, enable Settings > Windows & storage > Copy dictation to clipboard. Completed dictation then replaces your previous clipboard contents, even if automatic insertion is blocked. It works with clipboard paste or Unicode typing. The option is off by default; cancelled/test takes, failed-cleanup raw text and code requiring review are excluded. If an error warns that some text may already be inserted, inspect the field before pasting again.

The Test dictation button records a test take and shows its result in CridVoice. It does not insert into an unrelated application. Use global shortcuts for cross-application insertion. The tray Toggle dictation command also records into the current target.

Ctrl + Shift + Space starts recording with one press and finishes with the next. Escape cancels. The recording-length limit automatically ends a recording; the default is five minutes. Longer sessions can be selected in Settings.

The compact floating bar appears at the bottom center of the primary monitor's usable desktop area, with its status label and waveform centered within the popup. It shows recording/processing stages and up to two visible lines of live preview. Turning preview off makes the card shorter. Appearance provides independent controls for the waveform, preview, and whole bar. Live recognition is provisional and depends on inference speed. Final processing may revise it after you stop.

With local speech and live preview enabled, setup/repair includes Whisper Tiny, a separate CPU preview model of about 75 MiB. Its first request becomes due at about 750 milliseconds, then at minimum 300-millisecond intervals when free. Recognition still arrives in provisional chunks, so it can revise words rather than displaying every spoken word instantly. Only the latest six seconds are previewed; older words can leave the preview. Your selected final speech model independently recognizes the complete take after release, with its normal settings, then cleanup runs. Remote preview keeps its existing provider and cadence.

The popup's fixed two-line area follows the newest words. Overview follows updates while you are near the bottom; scrolling back keeps your reading position until you return near the bottom. The full current preview remains accessible without a live announcement for every partial word. A preview-only failure can show Preview unavailable. Release to transcribe. while final recognition remains available. You can turn live preview off in Appearance without changing the selected final speech model.

Lower background audio

In Settings → Speech recognition, turn on Lower background audio while speaking, then adjust Background audio reduction from 10% to 90%. Higher values make other apps quieter. The default 60% reduction leaves playback at 40% of its original session volume. The switch is off by default; the slider remembers its amount when switched off.

The displayed amount follows the slider immediately. Release the slider, finish a keyboard adjustment, or leave it to save the amount. It applies to the next recording. The volume returns when you stop or cancel, before final recognition and cleanup. Observed manual volume changes during recording are kept. Settings stays visually stable while ordinary saves complete in the background.

This lowers computer playback such as music or a video. It does not remove room noise from the microphone recording. See Troubleshooting for supported playback devices and restoration behavior.

Speaking naturally

Cleanup resolves corrections such as:

Spoken input Intended result

“At five, sorry, six in the evening.” “At six in the evening.”

The editing prompt instructs models to preserve uncertainty, names, facts, quotations, meaningful alternatives, language choices, and Polish characters. Ambiguous revisions cannot always be resolved reliably. Check important output, and compare raw versus cleaned text in History. English and Polish

Automatic mode leaves language detection to the multilingual speech model. It preserves the recognized language rather than translating. Mixed-language recognition varies by model and utterance. Use the language selector on Overview or in Settings for an explicit English or Polski override when detection is wrong or you need predictable language behavior.

Code and CLI

Choose the output mode on Overview or in Writing styles. Both technical modes require text cleanup to be enabled, using the selected local model or text provider. Choosing cleanup Off returns output to Text. They reuse your speech model and shortcuts; no additional coding model is downloaded.

Output mode What to say What happens
Text Ordinary dictation Cleans up prose and inserts it into the original text field.
Dictate code or commands The code or command itself, including symbols and flags Treats the utterance as literal code, with instructions to preserve identifiers, operators, quoting, paths, and layout. Uses normal target-field insertion, except multiline output to a recognized terminal goes to review.
Generate code or commands Instructions describing the code or command you want Produces code, opens CridVoice for review, and lets you choose Copy. It does not automatically insert the generated result into an editor or terminal.

Output mode is your choice; automatic language detection does not change it. Under Code language or shell, choose Automatic, a common language/shell, or Other / custom…. Automatic applies only to the language/shell used by code and command modes. When application context is enabled, it can use available editor/window titles, filename hints, selected or nearby text, and shell prompts. Where those hints are unavailable, it follows your spoken request and the model's interpretation.

Common choices include PowerShell, Windows CMD, Bash, Python, TypeScript, Rust, and SQL. Detected or Last detected shows the available language result. This control is separate from the English/Polish speech-language selector. Password fields remain excluded from context.

Clear command starts such as git status take precedence over unrelated nearby Python code or an editor filename. When a shell cannot be identified, the result can show Command line rather than assuming one. Manual and explicit spoken language hints still take priority. Arguments and quoted text keep their case. Spell branch names with the intended dash, slash, quoting, and spacing; the app does not invent a dash or join ambiguous words.

For generation, choose Generate code or commands and describe the goal, for example: “In PowerShell, list the log files in C:\Logs, newest first,” or “Write a Bash command that finds Python files below the current directory.” Review the plain code in CridVoice, then use Copy and decide where to paste it. The app does not run generated code. Literal multiline output to a recognized terminal also opens for review. A terminal can interpret a multiline paste differently from an editor, so inspect commands and their line breaks before pasting or submitting them. Literal command insertion adds no Enter action; press Enter yourself when ready.

If cleanup or conversion fails, the retained speech is labelled Raw transcript and history shows conversion failed. It is not presented as finished code or inserted automatically. If generation succeeds but history saving fails, the valid result remains available for review and Copy.

Recognition and code quality depend on the selected speech and cleanup models. Auto detection and manual hints do not establish accurate support for every language. Add exact identifiers or commands to Vocabulary, such as Get-ChildItem with the alias get child item, or kubectl with kube control. Aliases are hints, not guaranteed substitutions. Include intended casing, switches, paths, and quoting when speaking.

Rewriting selected text

Select text in the target application. Press Ctrl + Alt + R, say the change you want, and press the shortcut again to finish. Examples: “Make this shorter, but keep the deadline,” “Change the tone to friendly,” or “Przepisz to bardziej formalnie.” The selected text is replaced with the model's answer.

This requires application context and text cleanup. Selection retrieval depends on the target app's Windows accessibility support. Missing selection produces an actionable error. If focus changes while processing, CridVoice saves output instead of typing into another field.

With text selected, the ordinary hold shortcut also recognizes explicit spoken instructions such as “Rewrite this…,” “Make this shorter…,” “Translate this…,” “Przepisz to…,” and “Skróć to….” These cues activate rewriting only when a selection exists and cleanup is enabled. Otherwise speech is treated as normal dictation. Quoted commands or incidental mentions do not match the prefix-based command detector.

Vocabulary

Add a correct spelling and optional comma-separated aliases. Words are supplied as recognition hints and editing context. Useful examples include “CridVoice” with “crid voice,” “Łukasz” with a common mishearing, and exact code identifiers. Hints improve the chance of recognition; they are not unconditional replacements. Remove a word with its trash button. Search filters words and aliases.

Ordinary Text and literal code dictation use only the new spoken take as source material. Existing selected or nearby text is not included in their cleanup request, even with application context enabled. Explicit rewrites can still edit selected text, and code language detection still uses available context.

Writing styles

Choose Natural, Professional, Casual, Concise, or Technical as the default for Text output. Style controls tone: Natural keeps your voice, Professional uses polished phrasing, Casual is conversational, Concise shortens wording while keeping each point, and Technical preserves identifiers in prose. Add app-specific rules using an executable-name substring such as outlook, slack, or code. Rules are matched case-insensitively; the first matching rule wins. Optional custom guidance accompanies that rule. Rules require cleanup to be enabled.

The separate Rewrite strength setting controls how much Text wording can change. Light makes grammar/punctuation edits close to your wording. Balanced smooths unclear sentences. Thorough can regroup a longer brain dump into a coherent message. Rephrasing is permitted; inventing details, reversing a negation or changing uncertainty is not. Strength applies across Text styles and application rules; it does not change code/CLI formatting or the speech model. Existing settings default to Balanced. AI editing can still make mistakes, so important details should be reviewed.

The Application selector groups common apps, recent History app names, and running visible-window process names. Refresh updates the running list; protected processes can be absent. Choose the custom option for an unlisted executable stem or substring. Existing rules can be edited without removing/recreating them. The running list uses names only, not window titles, document text, paths, or command lines.

Use How should CridVoice write for you? to set personal wording and tone preferences. For example: “Keep my slang, including bro. Do not add pet names or greetings. Use short paragraphs and avoid corporate wording.” Choose Save preferences to apply the draft, or Use defaults to clear it. The box accepts up to 2,000 characters. Preferences apply to every Text style and rewrite strength, including Balanced and Thorough. Slang, nicknames and forms of address are preserved by default; a stronger rewrite is not permission to replace “bro” with “buddy.” Explicit preferences can request a different tone while facts, uncertainty and intended meaning still come first.

The first matching application's Extra guidance for this app can refine your general tone or formatting preferences. Personal guidance does not change code/CLI modes and has no effect while cleanup is off. It uses the existing cleanup request, without another model call. Preferences are saved in local settings and included in requests to your selected text cleanup model or provider.

The You say / CridVoice writes example updates with both style and rewrite strength. These local illustrations use default preferences and show different wording and structure while retaining the example's facts, uncertainty and requests. Arbitrary personal instructions do not regenerate this illustration. Examples make no provider or model requests; exact AI wording may vary. Cleanup Off and code/generation modes show explicit notices because writing styles apply to Text cleanup.

The Technical writing style is a text-cleanup preset, stored under the existing code style ID for compatibility. Use the dedicated Output mode controls for literal code dictation or generation from instructions.

History

Final and raw transcript text are saved automatically by default. Audio is not saved as history. Search finds text or application names; the language filter selects English or Polish. Open an entry to compare original recognition with cleanup. Copy, delete, export filtered history as JSON, or clear all history. Retention can be indefinite, 7, 30, or 90 days. Turn recording of future history off in Settings without deleting existing entries.

History counts drive Overview statistics. Estimated time saved compares typing at 40 words/minute with recorded speech time. Entries which were not inserted are labelled saved transcripts and remain available to copy.

Successful code and generation entries preserve whitespace in a monospace view and scroll within the result or history dialog when needed. Long prose wraps within the page. Entries labelled Raw transcript · conversion failed contain retained recognition rather than converted code.

Appearance

Eight presets: Amethyst, Ocean, Forest, Rose, Ember, Graphite, Midnight, and Lagoon. Under Theme and color mode, select Light, Dark, or System mode. Color and text size lets you override the accent and scale text from 85% to 140%. Customize waveform, live preview, and the floating bar independently.

Presets apply to the background, navigation, cards, raised surfaces, hover colors, and borders. Selecting a preset also selects its accent while preserving text size, color mode, and recording-bar preferences. A custom accent survives saving/reopening and color-mode changes until another preset is selected. System mode follows the current system preference, including the theme previews. Custom accent text uses a derived foreground color to remain readable. Scrollbar tracks, thumbs, and corners follow the active theme and color mode. Buttons show a neutral hover state and a visible keyboard-focus outline; destructive actions retain a red tint/border with readable text.

Tray and startup

Closing the main window hides it in the tray. Open CridVoice restores it. Quit CridVoice stops recording and local processes and exits. Startup is opt-in, starts with --background, and uses the Windows current-user startup registration. Portable startup refers to that folder; update the setting after moving it.

Models and hardware

Processing stages

Speech recognition and text cleanup are separate. Speech uses faster-whisper / CTranslate2; cleanup uses a managed llama.cpp server or the selected external provider. Audio recognition does not become available merely because a text LLM is loaded in LM Studio.

Component Default Hardware
Speech Whisper Large v3 Turbo NVIDIA CUDA or CPU
Lighter speech Whisper Small NVIDIA CUDA or CPU
Live preview Whisper Tiny, separate from final speech Low-priority CPU, two threads
Text cleanup Qwen3 4B Q4_K_M llama.cpp Vulkan GPU or CPU
GPU speech runtime cuBLAS 12.9.2.10 + cuDNN 9.27.0.42 NVIDIA driver required
Text runtime llama.cpp b11559 CPU or Vulkan

The exact URLs, sizes, and SHA-256 hashes are in src-tauri/resources/model-catalog.json. Speech model revisions and GGUF revisions are pinned. GPU speech libraries are downloaded only when selected. Python and Python inference dependencies are already packaged.

RTX 5070 Ti

Use a current NVIDIA Windows driver. Install the NVIDIA speech runtime for CUDA recognition; having an NVIDIA card without its speech libraries is insufficient. The runtime uses CUDA 12.9 libraries, supporting the RTX 50-series architecture. The text engine uses Vulkan to avoid a separate CUDA-version dependency for llama.cpp.

Select Automatic to prefer detected NVIDIA hardware, GPU to require it, or CPU to avoid it. CridVoice uses nvidia-smi to detect NVIDIA cards and memory. Detection is not a successful inference test. If detection fails, Automatic chooses CPU. If GPU inference fails, the app reports it; it does not silently send data to cloud or switch providers.

Intel and AMD CPUs

Select CPU for both engines. Speech uses int8 compute; GPU speech uses int8/float16. CPU threads are capped at 16 in the speech worker. Whisper Small provides a lighter multilingual option; larger models can be slow on CPU. CPU text inference uses zero GPU layers. The runtime chooses its compatible CPU backend from the shipped llama.cpp distribution.

Memory and latency

The Models page separates your Selected configuration, Installed files on disk, and Models in memory. Live local engine status identifies the actual resident final speech, CPU preview, or cleanup model and device as unloaded, loading, loaded, or error. In 0.1.4, installed selected local engines warm automatically in the background after launch. A selected or installed model is not ready merely because its files are on disk. Overview shows warming while preparation runs, and a silent take can still complete without loading speech weights.

Model changes update every app window through events. A backend check every two seconds also detects exited inference children and changed installed markers. The page refreshes automatically without reloading or restarting CridVoice. External LM Studio, llama.cpp, or cloud model residency remains under that provider's control; CridVoice reports its own managed engines.

Keep VRAM free for both models. Both engines can remain loaded between takes to reduce latency. LM Studio, games, and other GPU work can compete for memory. Use Unload models from memory when idle to release workers and their allocations, or choose CPU for one stage. Explicit unload cancels pending warming and keeps the engines unloaded; use the manual loading action or dictate again when ready. Cold loading still takes time just after launch or unloading. Background warm-up moves that work ahead of the first take where possible; it does not remove hardware initialization costs.

Local live preview uses a separate Whisper Tiny CPU worker with two threads and low process priority. Its pinned download is 78,203,619 bytes, about 75 MiB. It processes only the latest six seconds and produces revisable chunks rather than true per-word callbacks. The selected final model keeps its separate worker, device, warm state, and full-audio recognition settings. This isolates its worker lock and GPU allocations from preview, while shared CPU/system resources can still affect timings. Turn preview off for the lightest CPU workflow.

The independent local preview skips a busy worker instead of queueing and has a five-second request budget; preview warming allows thirty seconds. Final speech queue/processing limits remain 60/240 seconds. Managed cleanup startup allows 120 seconds and chat requests allow 180 seconds. These are separate stage budgets. A failure reports an error without switching to cloud or another provider.

On the Windows validation machine, original and updated packaged workers both recognized a short synthetic English fixture using Whisper Turbo on CPU and RTX 5070 Ti CUDA. The updated worker also reported its loaded model/device and cleared that status on unload. This establishes a narrow worker smoke pass, not real microphone quality, Polish accuracy, or complete desktop behavior. See the dated Windows report.

Cleanup requests cap output at 4,096 tokens. Truncated model responses are rejected; the recognized transcript is preserved instead of silently inserting an incomplete edit. A model's context/output limits can require shorter takes, especially with large selected text or long recordings.

Download lifecycle

The setup wizard derives the complete local component plan from both selected stages and devices. Local speech needs its final speech model plus NVIDIA runtime when using CUDA. Enabled local live preview additionally requires the separate Whisper Tiny asset; disabled preview or provider speech does not. Tiny appears in its own Live preview group and cannot be selected as the final speech model. Managed cleanup needs Qwen3 plus the selected CPU/Vulkan engine. Automatic prefers detected NVIDIA hardware; explicit Vulkan cleanup GPU is not limited to NVIDIA. Provider-based stages and disabled cleanup omit their local requirements.

The final wizard step names every required component and shows the missing download total. Install required components & finish automatically installs missing components sequentially, skips already-installed assets, and keeps visible overall/per-component download and verification/extraction progress. Pause setup, Resume setup, and Retry setup preserve usable partials and installed components. Completion requires a fresh installed-state snapshot and a native readiness check; an unfinished local plan cannot be saved as completed setup.

If an existing app lacks selected components, use the repair wizard instead of manually downloading files outside CridVoice. Fully provider-based routes require no local downloads. A browser preview cannot establish local installed readiness.

Downloads stream to .part files in the model directory, support valid HTTP byte ranges on retry, verify expected size and SHA-256, then rename atomically. Runtime ZIP/wheel contents are extracted with path and symbolic-link checks. A model is marked installed only after every file is verified and extraction completes.

Pause retains partial data for resume. A network interruption also retains partial data. A hash mismatch removes the corrupt partial file. Removing a model unloads engines before deleting its directory. Removal/unloading is rejected while dictation is active.

Shown sizes are compressed download totals. Keep additional disk space for extracted runtimes, temporary files, and models. NVIDIA libraries in particular can occupy substantially more than their download size. All model downloads are explicit; completed models can run offline.

Maintaining the catalog

python scripts/update_catalog.py is a maintainer operation requiring network access. It refreshes metadata at already pinned revisions and releases. Review the generated URLs, licensing, file sizes, and hashes before committing any source or version change. An ordinary app session never resolves a floating “latest” model or executes remote code from a model repository.

Providers

Independent routing

In Providers, create a connection. In Settings, select it for text cleanup and/or audio recognition. A provider being listed does not activate it. Local is the initial default. Errors never cause automatic cloud fallback.

Protocol Text endpoint Audio endpoint
OpenAI compatible <base>/chat/completions <base>/audio/transcriptions, when supported
Anthropic compatible <base>/messages Not used; choose local or an OpenAI-compatible speech provider

Provide the API root, normally ending in /v1, not an individual request URL. A bare origin gets /v1 appended. Custom paths are retained; a trailing slash is normalized. Remote endpoints require HTTPS. HTTP is permitted only for localhost/loopback. Credentials in the URL, fragments, and query strings are rejected.

Choose model IDs

In setup or the provider editor, configure the endpoint/protocol and choose Fetch models. This explicitly sends a model-list GET request to that draft endpoint; opening the editor does not contact it. Select returned IDs for text and, for OpenAI-compatible speech, audio. A listing does not classify capabilities or prove account access. Use Enter a custom model ID for an unlisted model or a server without discovery; Not selected clears an optional speech choice.

Discovery sends no dictation or application context and runs no model. Typed draft keys are not saved by Fetch. A saved key is read only when the provider ID, protocol, and base URL match the current saved connection exactly; otherwise supply a typed key or use an unauthenticated server. Requests do not follow redirects and have bounded time, response size, and model count. The picker preserves current selections and ignores stale replies after endpoint/key changes. Endpoint presets do not establish model/account availability.

LM Studio

  1. Load an instruction-following model in LM Studio.
  2. Start its local server and check the port.
  3. Add the LM Studio preset (http://127.0.0.1:1234/v1). Use Fetch models, or the custom fallback with the exact model ID shown by the server; discovery availability varies by server version.
  4. Save and use Test. The test sends a short “READY” request, not your dictation or application context.
  5. In Settings, select Selected provider under Text cleanup and choose that connection.
  6. Keep local speech selected and download a speech model/runtime, unless you separately selected a compatible audio API.

LM Studio remains independently managed. CridVoice does not start/stop its process or change its loaded models.

llama.cpp

Start your own llama-server with a compatible GGUF and listen on loopback. The preset is http://127.0.0.1:8080/v1. Enter the server's model ID, plus its API key if enabled. Select it for cleanup. The managed local mode is separate: CridVoice launches its own bundled/downloaded engine, chooses a free loopback port, and creates a per-session API key.

OpenAI and compatible cloud APIs

Use the OpenAI preset or a custom base URL, an API key, and the exact text model ID. For cloud speech, also set a supported speech model ID and select that provider under Speech recognition. Standard audio requests use multipart WAV uploads and JSON responses. Compatible providers must actually implement the chosen endpoint and model.

Text requests send system/user messages, nonstreaming chat completions, and an output token limit. Generic compatible servers use max_tokens; direct OpenAI uses max_completion_tokens, and known OpenAI reasoning model families omit unsupported temperature controls. Other models use temperature 0.1. Local template options are sent only to the app-managed server; they are never included in cloud requests. Returned <think> blocks are removed. Some providers may require a model-specific configuration change or a different compatible endpoint. Endpoint presets do not establish account/model availability; choose a returned ID or enter an explicit custom ID.

Anthropic and compatible APIs

Use https://api.anthropic.com/v1 or another compatible API root. Enter a model ID available to your account. Requests use x-api-key, anthropic-version: 2023-06-01, a separate system prompt, messages, and max_tokens. Only text blocks are extracted from the response. Use local recognition or another configured audio provider for speech.

Credentials

Keys are first encrypted with Windows DPAPI in the current-user scope, with connection-specific entropy. Only the versioned ciphertext is stored in Windows Credential Manager under service CridVoice and the connection UUID. CridVoice never writes raw keys to files or returns saved keys to React. Decrypted Rust buffers are wiped on drop; OS decrypted buffers are wiped before release. Settings retain only whether a key exists. Leaving an existing key field blank preserves it. Removing a provider removes its stored key. Portable keys remain associated with the Windows user and computer; transferring the folder does not transfer keys.

Before key lookup, a waiting request rechecks that its provider ID, endpoint, and protocol still match current settings. Changing or removing that connection makes the request fail with a retry message. Key rotation at an unchanged endpoint remains supported.

Context and costs

When you select a remote cleanup provider, the recognized transcript, enabled application context, vocabulary, and style guidance are sent to that provider. A remote speech provider receives audio. Live cloud preview may send multiple snapshots; disable preview to send only final audio. Account charges and provider retention follow the selected service's settings. There is no CridVoice account, subscription, or hosted intermediary.

Error handling

Connection, timeout, authentication/model, and invalid response errors appear in the app. Cleanup failures preserve the raw transcript and do not insert uncleaned text automatically. Transcription failures cannot recover text that was never recognized. Audio is discarded after processing or on the next launch following a crash.

Privacy and storage

Local defaults

Initial settings use managed local speech and cleanup. There is no telemetry, account, hosted application backend, or automatic cloud fallback. The speech worker uses local-only model loading and sets Hugging Face offline/telemetry flags during inference. Model downloads are separate, explicit setup/Models operations.

Setup lists the exact components required by the selected speech/cleanup stages and the missing download size. Choosing Install required components & finish starts those downloads automatically inside the wizard; there is no separate hidden download opt-in. It reuses installed assets and preserves usable partials on pause/retry. Merely opening repair does not begin network downloads. Fully provider-based stages do not download local models, and download/inference errors never choose a cloud provider automatically.

Repair keeps the existing independent provider IDs and saved credential architecture. Saved keys remain encrypted in Windows Credential Manager; leaving a key field blank performs no credential write. Setup is completed only after required local components and selected provider configuration pass readiness checks. These checks establish configuration/file readiness, not provider authentication, model accuracy, or an already-loaded model.

The speech worker explicitly disables ONNX Runtime telemetry events before creating inference sessions, in addition to Hugging Face telemetry controls.

Local inference/provider HTTP requests use a client that bypasses proxies for loopback traffic. Provider inference requests do not follow redirects, preventing an HTTPS endpoint from redirecting sensitive requests to another destination or to plaintext HTTP.

Fetch models explicitly requests model IDs from the draft provider, with the same endpoint restrictions and no redirects. It sends no audio, transcript, or application context and does not run a model. Unsaved typed keys are held in wiped-on-drop Rust buffers for the request; Fetch does not persist them. Saved credentials require exact provider ID/protocol/base-URL binding under the current settings lock. Returned IDs are transient choices, not a capability database or transcript history.

The application-rule editor obtains a bounded, deduplicated list of process names for visible top-level windows when opened/refreshed. It does not retrieve window titles, text, executable paths, or command lines for this list. Recent choices come from existing History app names. Choosing a rule saves its executable-name matcher, style, and optional guidance through the existing settings schema.

Audio lifecycle

Rust captures microphone PCM in memory during recording. Provisional snapshots and final WAV files are written to the private recordings/ directory for the Python worker or selected audio provider. WAV files are removed after their requests complete. Cancel invalidates the operation and prevents insertion; an already-running inference request can finish before its temporary file is removed. Crash leftovers are deleted on the next launch. Audio is never included in transcript history. Local live preview sends only a rolling six-second audio snapshot to a separate two-thread CPU worker using installed Tiny weights. Provisional text remains session state; it is not separately written to History. Final recognition and cleanup use the complete take independently. Tiny is downloaded only through an explicit setup/repair or Models action, and only local speech with live preview enabled requires it.

Transcript history

History contains original recognition and final text, language, application executable name, recording duration, mode, insertion status, and timestamps. It is a local SQLite database with a write-ahead log. History is plaintext in the user's application directory; it is not encrypted by this app. Protect the Windows user account/disk, or disable history. Clearing history also checkpoints/truncates the WAL and vacuums the database. Individual deletion uses SQLite secure-delete behavior; storage backups are separate from live deletion.

Retention removes expired entries when history is saved and at startup. The display/query limit is the newest 10,000 entries; indefinite retention may contain older rows. Exporting history creates a user-controlled JSON file containing the filtered text and metadata.

Application context

When enabled, the Windows UI Automation interface reads selected and nearby text from the focused control, bounded to approximately 2,048 characters each, and obtains the application executable name. It does not take screenshots or continuously scrape other applications. Password controls reported by accessibility are excluded and recording/insertion is refused for detected password fields. Controls without accessible text expose no surrounding text; accessibility implementations can vary.

Context is captured at recording start and used only for that session. Ordinary Text and literal code cleanup exclude selected and nearby text from model requests. Application style/vocabulary and locally derived language hints remain available; explicit rewrites and generation can send their permitted selected/nearby context. An output focus check compares the original window and accessible control identity; changed focus prevents insertion. No clipboard content is read for context. Default insertion temporarily places the final text on the clipboard, pastes it, and restores the prior supported formats. If the clipboard changes during paste, newer contents are preserved. When a format cannot be safely backed up before clipboard changes or input begin, CridVoice uses Unicode typing without changing the clipboard. Busy-clipboard, paste, or restoration errors do not trigger another insertion attempt. The temporary text carries Windows markers excluding it from clipboard history/cloud upload; third-party clipboard managers may implement their own behavior. Optional Unicode typing avoids clipboard use.

The clipboard insertion lease uses a unique per-paste marker and exact Unicode text to verify the temporary publication after the write handle closes. A changed sequence needs fresh proof before insertion or restoration; foreign clipboard updates remain protected. The marker is used locally for this operation.

Optional Copy dictation to clipboard deliberately leaves completed shortcut dictation on the clipboard after insertion or a focus-related insertion failure. It is off by default, works with either insertion method, and replaces previous clipboard contents at completion. This is separate from temporary paste restoration. Cancelled/stale takes, test recordings, failed-cleanup raw fallbacks and output awaiting code review are excluded. Persistent copies also carry Windows clipboard history/cloud/monitor exclusion flags; third-party clipboard tools may implement their own behavior. Clipboard text remains readable by applications with clipboard access until replaced.

Technical output

Code dictation and code generation use the selected speech and text engines. A selected cloud speech provider receives audio; a selected cloud text provider receives the recognized request and permitted editor/file/shell hints. Literal dictation excludes raw selected/nearby text; explicit rewrites and generation may include it when enabled. Credentials and local model server

Recording and state

When general.duckBackgroundAudio is enabled, a recorder-owned guard queues per-session playback reduction on a dedicated Windows MTA thread. Stop/cancel/Drop invalidates the take token and queues restoration without waiting in the final-recognition path. Session-created notifications discover new sessions on the existing active outputs; there is no polling loop. Sessions belonging to CridVoice and system sounds are excluded. The guard restores only an unchanged scalar that it applied, and volume-change notifications retain user adjustments. Normal tray exit allows a bounded restoration wait.

History's inner view is memoized separately from session/audio events. Filtering is cached by history, language and query; an empty query skips transcript-string normalization. Integer-format microphone callbacks convert samples while downmixing rather than allocating an intermediate normalized buffer. The final resampler and recognition settings are unchanged.

Background local-model preparation uses a separate warm-up epoch from recording sessions. Final speech, CPU preview, and cleanup prepare behind their individual engine locks, using only installed selected app-managed routes. Queued work rechecks its ticket before starting; route changes, explicit unload, maintenance, and shutdown invalidate stale preparation. Warm-up does not capture audio or application context, use history or provider credentials, or make external-provider calls. Its engine-status events leave the recording session idle and keep recording available.

Speech preparation validates the selected model/device, shares the transcription cache, initializes lazy ONNX VAD with one second of internal zero audio, and consumes a bounded encoder/decoder pass. Its generated result is discarded and never saved. Managed cleanup starts the selected loopback server and completes a tiny representative prompt using public defaults and the current output mode only. Loaded status follows completion of these warm requests; queuing a request alone does not establish readiness. A cancelled warm request retires its worker while still holding the engine lock before maintenance can proceed. Explicit unload suspends automatic preparation until deliberate loading/use, a selected-route change, or restart.

Idle → Recording → Transcribing → Cleaning → Inserting → Idle, with error/cancel paths. Recording is created on a dedicated thread so CPAL stream ownership is independent of the async executor. Input channels are averaged into mono, and a windowed-sinc resampler produces 16 kHz signed 16-bit WAV data.

The controller snapshots the focused application/selection and tracks a generation number. Cancelling increments the generation; obsolete preview/final results cannot insert text. A lifecycle lock and ordered action queue serialize recording transitions. Cancellation can invalidate a pending result without waiting for model inference. Local preview uses its own low-priority two-thread --preview-worker Python process and mutex, fixed to whisper-preview/CPU. One request at a time processes at most the latest six seconds, with a first opportunity around 750 ms and a minimum 300 ms start interval; busy opportunities do not queue. Preview replies replace the provisional recent-speech string, including corrections and shorter revisions. Recording generation and active-take checks discard stale results. After a successful send, the dedicated lane drains its reply so it cannot poison the next request. Final full-audio recognition uses the independently warm selected speech engine and its original decoding options; it does not wait for the preview mutex. Remote preview preserves its original provider/cadence. Microphone metering continues to emit regular session events. Audio limits bound memory and file sizes.

The preview path is greedy, skips word/timestamp output and prior-window conditioning, and caps each preview decode at 64 new tokens. It does not provide a true per-word callback. The UI shows the latest two lines in a fixed popup without animation, retains all current-window text in the accessible DOM, and avoids per-word live announcements. Overview follows text changes while near the bottom, not meter events, and preserves manual reading position. Neither surface stitches rolling hypotheses into a final transcript.

The recording bar labels the current stage as Recording, Transcribing, Cleaning, or Inserting and shows Escape cancellation during processing. These labels describe application progress, rather than establishing that a model or target application has succeeded.

The low-level Windows keyboard hook tracks left/right modifier keys. It ignores injected downs and ordinary injected keys; injected modifier ups can clear state or stop, but never start a shortcut. Before each physical event it clears other stale cached modifiers using Windows async state, without adopting async downs or checking the current key before Windows updates it. Suppressed Windows downs retain ownership through repeats and their eventual physical up; when a hold ends, they require that up and a fresh down to rearm. Forwarded Windows downs keep their releases forwarded. Physical shortcut-related downs alone can start actions, and work is dispatched out of the hook callback. Modifier-only Ctrl+Windows is supported directly; ordinary global shortcut libraries cannot represent that chord consistently.

Context and insertion

A dedicated MTA worker retains its UI Automation client and the most recent original editor provider rather than recreating the COM apartment on every probe. Requests have a 500 ms response timeout, a single queued slot and expiry checks; UIA connection/transaction timeouts also bound ordinary provider calls. Text fragments normalize only to the nearest actual editable host, and its native ancestor must belong to the captured foreground window. Ordinary field matching remains exact. A recreated field is accepted only if the retained original explicitly reports UIA_E_ELEMENTNOTAVAILABLE and both captures prove the same unique AutomationId, parent runtime ID, process and editor control type. Same window, similar text, geometry or a matching name are insufficient. Focus metadata is ephemeral and skipped during serialization.

Optional completed-result clipboard copying happens after temporary paste returns/restores and under the final lifecycle/generation lock. It deliberately replaces previous clipboard contents only for completed non-review dictation with successful cleanup, including a failed insertion attempt. It sends no keystrokes and never retries insertion. Preparation allocates all payload handles before EmptyClipboard, publishes privacy markers before Unicode text and transfers ownership only after each successful Windows call. Cancellation/stale takes cannot publish through the final commit.

Ordinary Text and literal code cleanup exclude selected/nearby text from the model payload. Code-language detection still derives hints locally from permitted context. Explicit rewrites and generation can use their permitted context. Each take has a fresh audio buffer and generation; final insertion uses only that take's output.

Windows UI Automation reads a focused control's selected text and text/value pattern, avoiding detected password fields. It captures the window handle and UIA runtime identity. Before insertion, those are checked again and physical modifiers must be released. Default clipboard paste uses owned copies of existing formats, Windows history/cloud suppression markers, and sequence-aware restoration. A typed preservation failure before clipboard mutation or input permits Unicode fallback; other errors never retry insertion, including a busy clipboard, open failure, missing clipboard-owner window, or failure at or after the write boundary. The Unicode path rechecks focus, password exclusion, cancellation, and modifiers, rejects missing foreground windows, and stops batches after focus changes or partial sends. A partial-input error says some text may already have been inserted. It never simulates Enter to create paragraphs. Unicode typing is also a selectable clipboard-free primary method. Focus changes, privilege restrictions, or rejected input preserve transcript text and surface a copyable result.

Input-event acceptance does not prove a particular application displayed the text. Browsers, Electron applications, terminals, remote desktops, games, secure desktops, and elevated processes require real target-app tests. Windows UIPI prevents a normal process from injecting into higher-integrity applications.

The temporary clipboard publication is proved after the write handle closes, using its owner, a unique per-paste marker, and exact UTF-16 text including the terminator. A sequence change requires a fresh full proof under a read lock; input still requires the final sequence/owner identity. Drift during target validation permits at most three proof/target-validation passes with fresh focus/password/cancellation checks. One dispatch closure sends input at most once, including zero/partial-send failures. Restoration also rechecks publication proof under its own lock before replacing temporary data. Foreign changes reject the lease. If setting temporary formats fails, originals are restored before the initial lock closes. Close/post-write errors are terminal and never invoke Unicode fallback; a restoration error after input reports possible partial insertion.

Technical output selects normal text, literal code dictation, or generation from instructions through the same speech and selected cleanup engines. Auto language/shell hints can use bounded editor/window/file/nearby-text context when application context is enabled; a freeform manual hint takes precedence. Technical modes require cleanup and use mode-specific instructions for syntax and formatting. Mode-aware response handling strips a single model code fence while preserving code indentation. Generation skips the input-dispatch stage and opens the main window for review and Copy. Literal multiline code also requires review for recognized terminal targets. Session metadata includes outputMode, codingLanguage, reviewRequired, and resultIsRaw; history distinguishes code, code-rewrite, and generate from ordinary dictation/rewrite. Failed conversion retains raw recognition, clears the code-language tag, and uses code-raw, code-rewrite-raw, or generate-raw history modes. No schema migration is required. A valid generated result remains copyable if history persistence fails. No command executor is created, and no Enter keystroke is added. Terminal handling of manually pasted line breaks remains a target-application behavior.

Speech worker protocol

Technical response parsing also accepts a normally finished reply containing one tagged opening transport fence and no further fence delimiter, removing that wrapper while preserving the remaining code exactly. The provider's token-limit/truncation gate runs before this parsing; an omitted fence does not bypass rejection of truncated responses.

One JSON request per UTF-8 line on stdin; one response line on stdout. Requests have unique IDs. Inference libraries' output is redirected away from protocol stdout. Python validates audio paths under the recordings directory, WAV format, file size, known model IDs, language, and device. Models load lazily and are cached by model/device. Inference uses local-only files and disables Hugging Face telemetry/network behavior.

Example request:

{"id":"uuid","op":"transcribe","audio":"C:\\path\\recordings\\final-1.wav","modelId":"whisper-turbo","device":"cuda","language":"auto","preview":false,"vocabulary":[]}

Response:

{"id":"uuid","ok":true,"result":{"text":"Cześć.","language":"pl","languageProbability":0.98,"modelLoaded":true,"loadedModel":{"modelId":"whisper-turbo","device":"cuda"}}}

Operations: health, warm_model, transcribe, unload. A warm_model request contains only its ID, model ID, and CPU/CUDA device; it uses no caller audio. Success returns ready, warmed, and the actual cache identity. Repeated warming of that identity reuses its prepared cache; switching model/device or unloading clears warm tracking. Health never imports inference dependencies or loads a model, and short/silent transcription still returns without loading weights. Errors use ok:false and fixed application-authored messages. Invalid JSON, non-object requests, and oversized lines receive errors without stopping the worker. A private duplicate of stdout carries protocol responses; Python and native-library output use stderr. Rust applies separate queue/processing timeouts and retires failed workers. The Python process listens on no network port. The dedicated --preview-worker role accepts only whisper-preview, CPU, and preview:true; the ordinary final-speech role rejects that preview-only model. Preview failure changes only the preview engine status.

Managed text inference

CridVoice chooses a free loopback port, generates an API key, and launches the verified llama.cpp executable with the chosen GGUF, context size, one parallel slot, and CPU/GPU layers. It waits for /health before chat. The server is reused for the selected model/device and replaced when that identity changes. A Windows job with kill-on-close prevents orphaned children after parent exit.

Live model state

get_snapshot includes independent engineStatus.speech, engineStatus.preview, and engineStatus.cleanup entries. Preview reports the fixed Tiny/CPU identity; an absent preview entry in an older bridge is treated as status unavailable. Each entry contains state (unloaded, loading, loaded, or error), modelId, and device. Selection is the configured choice; installation records verified files on disk; loaded status reports a model resident in an app-managed worker. A Python process starting, a silent take, or an installed marker alone does not establish that a speech model loaded. Successful worker responses report the actual cached model. Cleanup becomes loaded after its managed server passes readiness checks.

Model and settings changes emit application-wide events so both the main window and recording bar refresh their snapshots. A backend monitor also checks child-process state and installed markers every two seconds, emitting models-updated when they change. It detects exited children and models installed/removed outside the current window. It does not re-hash every model file on each poll. The Models page updates without a reload or application restart. These statuses describe CridVoice's managed engines; they do not inspect which models an external server has loaded.

Classification uses fixed-size buffers and retains only fixed diagnostic categories, such as missing NVIDIA libraries, GPU memory, graphics backend, model loading, speech dependencies, permissions, port binding, or invalid requests. Persistence and failures

SQLite uses parameterized statements, WAL, secure-delete settings, a busy timeout, and chronological indexing. Settings write through a synced temporary file and atomic rename. Downloads are installed only after complete verification. Keys use Windows Credential Manager rather than settings JSON.

Cleanup failure preserves recognized text, reports the error, and does not automatically insert raw output. No stage switches to a remote provider on failure. Preview failure does not destroy recording; final recognition gets an independent attempt. Completed history is emitted as an event so UI counters refresh.

Setup and repair

The wizard starts from existing settings and infers its managed/external/cloud route. It preserves independent audio/text provider IDs, saved key flags, disabled cleanup, and ordinary settings until explicit choices change them. The selected speech and cleanup modes/devices determine required local assets; choosing a route label alone does not imply that every stage uses that route.

The final step displays every required model/runtime and the missing download total. Starting Install required components & finish awaits missing download_model commands sequentially, reuses installed components, and leaves the wizard open during download, verification, and extraction. Pausing signals the current native job; retry resumes usable partial files or verified archives. Each returned command is followed by a fresh snapshot check, and a final snapshot must confirm the entire selected plan before the frontend completion callback runs.

The native complete_setup command validates settings and selected asset/provider readiness on every completion, including repair of an already-complete configuration. Ordinary save_settings also gates a false-to-true setupComplete transition. The native check prevents a stale frontend from completing an unfinished local plan. Readiness uses installed markers created only after successful verification/extraction; it does not imply a resident model, successful provider authentication, or inference accuracy.

get_snapshot.activeDownloads contains a map of current progress keyed by catalog ID, allowing a reopened wizard to observe an existing job rather than start it again. Progress states include queued, downloading, verifying, extracting, complete, cancelled, and error. Optional stageCompleted/stageTotal bytes show current verification/extraction progress independently of download bytes. Concurrent download events update both the per-component and overall display. Terminal jobs are removed from the active map while their final event remains available to the interface.

If a download begins between the snapshot and install command, the wizard joins the exact native already-downloading response. Installed markers and the job map are read separately, so a finishing job can briefly appear absent from both. Three fresh checks at 500 ms intervals provide bounded completion coherence before reporting a stopped installation; neither that grace period nor joining a job bypasses the final marker/readiness checks.

Existing incomplete desktop settings open repair at the component list, and an attempted in-app recording also opens repair when requirements are missing. The Settings wizard entry remains available for later changes. Repair can close while idle; active setup must pause first. Browser preview cannot finish a plan requiring local assets. A fully provider-based route can save its preview configuration without claiming Windows/native readiness.

Troubleshooting

Speech is in History but did not insert

The transcript is saved before insertion, so a saved result does not prove the target field accepted it. Copy the result from History if needed.

CridVoice 0.1.16 rechecks a transient missing/different accessibility node for up to five samples, spaced 20 ms apart, accepting only the original window and field. Stable focus adds no wait. A real window change or password field stops immediately. It never forces another window into focus or replays input after a partial paste/type.

The message distinguishes a changed window, a different field and a field Windows could not identify. Keep the original field focused until insertion completes. If an app does not expose a verifiable input field through Windows accessibility, Copy remains available. For administrator apps, CridVoice needs compatible elevation; running normal applications normally is preferable.

Lower background audio

Settings → Speech recognition → Lower background audio while speaking is off by default. Background audio reduction controls the reduction from 10% to 90%; the new default is 60%. If 0.1.16's fixed 25% sounded too subtle, raise the slider and start a new recording. It affects supported per-session playback on currently active outputs and restores volumes after stop/cancel, recording errors, or normal exit. It leaves system volume, mute state, microphone and system sounds alone. Observed manual session-volume adjustments during a take are retained.

Windows audio support varies: exclusive-mode playback and devices connected after recording starts may not expose an adjustable session. An abrupt process termination or power loss cannot run normal restoration; use Windows Volume mixer if needed. This is playback reduction, not microphone noise removal. It adds no model or download.

Navigation labels are hidden

Choose Expand sidebar to restore page labels. Collapsed navigation keeps its icons: hover or keyboard-focus an icon to see its name, or use Ctrl + K to find a page. The collapse preference is remembered without changing your processing settings.

Header is dimmed while a dialog is open

The full-window backdrop dims the header and logo along with the page. Close the shared dialog before using header controls; a header click dismisses the dialog without also minimizing or closing the window. Tab or Shift + Tab returns navigation to the active dialog if a disabled action or dismissed toast left focus outside. Ctrl + K is ignored while another dialog is active. Setup keeps its existing busy and mandatory-close restrictions.

No microphone or no speech

Open Windows Settings → Privacy & security → Microphone and enable microphone access and desktop-app access. Check System → Sound → Input, choose the correct device, then use CridVoice Settings to refresh/select microphones. Bluetooth headset mode and other apps can alter input quality. Try a direct/built-in microphone. Silent takes intentionally produce no text rather than guessed speech.

Settings loads microphone choices when opened. Use Refresh microphones after reconnecting a device, or select Windows default microphone. A saved disconnected device is kept visible rather than silently replaced. Find a page accepts microphone/audio keywords, and Settings section buttons jump to the relevant controls.

Shortcut does nothing

Complete first-run setup, keep CridVoice in the tray, and ensure another app is not owning Ctrl+Windows. Test both key press orders and left/right keys. Check configured shortcuts in Settings. Avoid overlapping chords and remappers that intercept the Windows key. Use Test dictation to separate audio/inference problems from hotkey problems. Release both Ctrl and Windows between takes. Version 0.1.14 clears stale modifier state and requires a fresh Windows press after a suppressed hold ends.

If a second chat dictation repeats the earlier draft, update to 0.1.14. Ordinary cleanup now excludes existing selected/nearby text, while explicit rewrite still uses a selection. Compare History raw and cleaned text to distinguish recognition from cleanup, without reposting private content.

To change a binding, choose Change, press the chord, release all keys, and Save. Capture reserves Escape for cancel and stops after 30 seconds without a completed chord. Cancel or Try again does not change the saved binding. Fix the displayed conflict or restore a default. Close capture before testing dictation; no take should start while it is listening.

Provider model list is empty or cannot load

Check the draft API root/protocol/key, then choose Fetch models explicitly. A compatible text/audio endpoint does not necessarily implement model listing. Choose Enter a custom model ID when discovery is unavailable, incomplete, or unsupported. Returned IDs do not prove text/speech capability or account access. After changing an endpoint, supply a typed key or use no authentication; a saved key is never sent under a different provider binding.

Application is missing from writing-style choices

Use Refresh while the app has a visible window, or choose a common/recent entry. Protected processes can be absent. The custom option accepts its executable stem or a matching substring, not a window/document title. Existing rules can be edited. The first case-insensitive matching rule wins.

Model is not installed

Run setup repair to install the complete selected component plan. Local speech needs its selected final model, the NVIDIA runtime when using CUDA, and the separate Tiny model when live preview is enabled. Managed cleanup also needs its model and CPU/GPU runtime. A partial .part file is not an installed model; resume the download. After a checksum error, download again.

Selected, Installed, and Loaded have separate meanings. Selected is your configured choice. Installed means the files are on disk. Models in memory shows whether CridVoice's local final speech, CPU preview, and cleanup engines are unloaded, loading, loaded, or in an error state, including the actual model/device. Installed files can remain available while the managed engines are unloaded. Changes refresh automatically across app windows, with a two-second backend check for exited children or changed installed markers. No reload or restart is needed. External LM Studio/cloud model residency is controlled by that provider.

Processing takes too long

Local preview uses a separate two-thread CPU Tiny model, with the first request due around 750 milliseconds and minimum 300-millisecond hops while free. It recognizes a rolling six-second window in provisional chunks; words can revise or disappear as that window advances. Model warming and CPU speed can delay visible text. Final recognition independently processes the complete take using your selected final model; remote preview keeps its existing provider/cadence. Check the separate Preview memory status in Local models. If Tiny is missing, complete its visible setup/repair download. A preview-only error can show Preview unavailable. Release to transcribe. without replacing final recognition. Turning preview off removes that local component requirement.

The recording bar distinguishes Transcribing, Cleaning, and Inserting. Press Escape to cancel and prevent stale insertion. Record the displayed stage, model/device choices, and exact safe error before changing settings.

The independent local preview skips a busy lane instead of queueing and has a five-second request budget; preview warm-up allows thirty seconds. Final recognition retains a separate 60-second queue limit and 240-second processing budget. Managed cleanup startup has a 120-second readiness limit; chat requests have a 180-second HTTP limit. These limits apply to separate stages, so they are not a single total recording deadline. A timeout is reported without automatic cloud fallback.

To isolate the problem, disable live preview, select CPU speech with cleanup off, and use Test dictation. Then enable cleanup and GPU stages separately. Reuse an already-installed speech model; download Whisper Small only if you choose that lighter option. A reported Processing freeze in the original build has not yet been reproduced with a real microphone, so its cause remains unconfirmed.

Child process exits or cannot start

CridVoice now reports fixed diagnostic hints and numeric Windows error/exit codes where available. Categories cover NVIDIA libraries, GPU memory, graphics initialization, model loading, speech dependencies, permissions, port binding, and invalid speech requests. It drains child pipes concurrently and does not expose raw output, transcripts, provider responses, or command lines containing API keys. Share the safe error shown in the interface with the model/device and failing stage; a category is a troubleshooting hint rather than a confirmed root cause.

NVIDIA or DLL errors

Update the NVIDIA driver. Install the NVIDIA speech runtime through Models; CUDA speech requires cuBLAS 12 and cuDNN 9. CridVoice downloads pinned CUDA 12.9/cuDNN 9 libraries. Selecting GPU on a machine without NVIDIA speech support produces an error. Select CPU to diagnose independently, and use Whisper Small for lower resource requirements. GPU text runs through Vulkan, not the speech CUDA runtime.

GPU memory is full or inference is slow

Close other GPU-heavy applications or unload LM Studio models. Choose CPU for one stage or a smaller speech model. Disable live preview for long takes/CPU workloads. In 0.1.4, installed selected local models warm in the background after launch. Check the live warming/loaded state on Overview and Local models.
