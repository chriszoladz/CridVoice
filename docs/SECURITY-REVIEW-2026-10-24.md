# Security review, 24 October 2026

This is a focused source and dependency review for the 0.1.18 candidate. It is not a penetration-test certification or a claim that every dependency advisory is absent. Installation and real target-app acceptance are separate release checks.

## Findings addressed in this candidate

**HTTPS certificate trust.** The lockfile previously selected `rustls-webpki 0.103.15` and `webpki-roots 1.0.9`. These could accept paths through distrusted emSign intermediates whose private keys are publicly known. An attacker able to intercept provider traffic could impersonate a trusted HTTPS endpoint and obtain credentials or request contents. The candidate pins the patched `rustls-webpki 0.103.16` and `webpki-roots 1.0.10`. Other package versions were not broadly updated for this fix. Model SHA-256 checks independently protect downloaded model/runtime contents, but do not replace HTTPS trust for provider requests.

Sources: [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382.html), [RUSTSEC-2026-0381](https://rustsec.org/advisories/RUSTSEC-2026-0381.html).

**Unbounded AI response buffering.** Chat cleanup, audio transcription and local cleanup warm-up previously used `Response::json()`, which buffers the response before parsing it. A malicious or compromised configured provider could return an oversized response and exhaust memory. These paths now use a shared 2 MiB streaming limit, checking both declared Content-Length and accumulated chunks. Parsing and transport failures return fixed messages without response content. Four loopback fixtures cover oversized declared length, chunked overflow, a valid Unicode response exactly at the limit, and malformed content with a private-looking marker. Model-list discovery retains its existing separate 1 MiB limit. Native test results are recorded in the release verification, not inferred from this document.

**Development dependencies.** The official npm audit flagged the Vitest 3 / `@vitest/mocker` subtree and `tinypool`. The candidate updates only the direct development dependency to `vitest ^4.1.12`, locked at 4.1.12 with matching mocker; Vitest 4 removes the tinypool dependency. The post-update official npm audit reported **zero vulnerabilities across production and development dependencies** on this review date. That is a dated database result, not a permanent guarantee.

The mocker advisories require an exposed unauthenticated interceptor/mocker plugin registration path. The reviewed Vite configuration does not install those standalone plugins; Vitest runs unit tests in jsdom. Tinypool's reported execution gadget additionally requires upstream prototype pollution. These were dependency findings, not demonstrated remote execution in the installed CridVoice app. Sources: [Vitest redirect mock](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9), [Vitest manual mock](https://github.com/vitest-dev/vitest/security/advisories/GHSA-qxg6-89mg-rqv8), [tinypool run options](https://github.com/tinylibs/tinypool/security/advisories/GHSA-85c8-ppgw-ccpr).

## Reviewed boundaries

Provider URLs require HTTPS except literal loopback HTTP, reject user information/query/fragment fields, and inference/discovery clients do not follow redirects. Loopback requests bypass proxies. Saved-key lookup checks provider ID, protocol and exact endpoint under the settings lock; secrets remain DPAPI-protected in Windows Credential Manager. No configured provider or real credential was used in this review.

Download/remove IPC accepts known catalog IDs rather than arbitrary filesystem paths. Downloads have expected byte counts and pinned SHA-256 hashes before installation. The manual runtime extractor rejects traversal paths and archive symlinks and does not apply Unix permissions. Native folder/help opener commands use app-derived paths. Reviewed frontend output uses React text rendering; no untrusted HTML/eval sink was found. The candidate also has an explicit packaged-content CSP. This review did not attempt to compromise WebView2 or test hostile local processes with access to the same user's files.

The managed cleanup server binds to loopback with a fresh authentication key; speech workers use private pipes. Worker audio paths and model identifiers are constrained. Existing clipboard identity, cancellation, password and focus safeguards were reviewed alongside the separate focus corrections in this release. No live microphone capture, clipboard mutation or injected input was used for this audit.

## Remaining advisory scope

The 0.1.20 personalization change adds one optional writing-preference string, validated to 2,000 Unicode characters. Saved global and matching application guidance are explicitly identified as wording, tone and format instructions in Text requests. Source transcripts, quoted text, context and vocabulary remain separate data. Meaning, facts, uncertainty and current-take isolation remain higher-priority constraints. Code/CLI routing returns before these prose preferences are assembled. No tool execution, new network endpoint, extra model call or credential access is introduced. As with other model instructions, these boundaries guide output; tests cannot prove complete model compliance.

With active personal guidance, quotes and explicitly preserved layouts remain intact. Paragraph grouping requires a typed decision from the checked response, instead of interpreting natural-language formatting preferences a second time. Default formatting heuristics remain active without personal or matching application guidance. This avoids overriding a deliberate single-paragraph or quotation request; it does not guarantee that every free-form preference will be followed.

Active guidance also selects a strict object response with required Boolean `styleAccepted`, string `text` and typed `format` fields. The format is `preserve`, `paragraphs` or `singleParagraph`. Parsing rejects arrays, duplicate/unknown/missing fields, wrong types, trailing prose, fences, empty successful text and oversized replies. Only an actual leading reasoning block may be removed, preserving literal tags inside the JSON text. A negative style decision or protocol failure returns an error through the existing raw-transcript path and blocks automatic insertion and clipboard copying. This validates structure and enforces rejection; it is not independent validation of meaning when the model accepts a style. Managed local requests enable a bounded 256-token processing allowance only for this path; default Text, warmup and technical requests keep it disabled. No second model request is added.

The model's typed paragraph decision can authorize the existing bounded, whitespace-only sentence grouping for long prose. Other format decisions preserve the returned text. This reads a declared response field rather than interpreting the user's natural-language preferences again; it neither changes words nor inserts inside an existing structured layout.

Review found that multiline Text previously bypassed the terminal review guard. Both paste and Unicode insertion preserved its line breaks, which could submit earlier lines depending on terminal behavior. The 0.1.20 guard now covers multiline output in every mode when the target is a recognized terminal, using the existing process/prompt detection. Review blocks automatic insertion and persistent clipboard copy, shows the result in CridVoice and leaves copying to the user. Single-line terminal output and multiline ordinary-editor output retain their prior behavior. Unknown terminal hosts may not be recognized, particularly with context disabled.

An official RustSec database snapshot was compared locally with locked package names, then relevant version/platform/API conditions were reviewed. `cargo-audit` was not installed, so this was not a full cargo-audit run.

* The new `zip` extraction advisories ([0367](https://rustsec.org/advisories/RUSTSEC-2026-0367.html), [0368](https://rustsec.org/advisories/RUSTSEC-2026-0368.html), [0369](https://rustsec.org/advisories/RUSTSEC-2026-0369.html)) concern the library's extraction/symlink/Unix-permission paths. CridVoice uses its own checked file-copy extractor on Windows, rejects symlinks, and calls neither affected extract API. A disruptive zip 9 upgrade was not used to clear an unreachable warning.
* Tokio [0386](https://rustsec.org/advisories/RUSTSEC-2026-0386.html) concerns `tokio::io::unix::AsyncFd`, which is not part of this Windows target. GTK/glib and D-Bus notices likewise belong to non-Windows dependencies in the cross-platform lockfile. Unmaintained-package notices are tracked separately from demonstrated vulnerabilities.
* Locked rustls 0.23.45 is listed by [0346](https://rustsec.org/advisories/RUSTSEC-2026-0346.html), [0347](https://rustsec.org/advisories/RUSTSEC-2026-0347.html), [0348](https://rustsec.org/advisories/RUSTSEC-2026-0348.html), and [0349](https://rustsec.org/advisories/RUSTSEC-2026-0349.html). The app has no custom session-store secret logging, enabled ECH or Brotli certificate decompression. Its ring provider does not provide the described hybrid post-quantum key share. These prerequisites were not found in the current Windows configuration; rustls 0.23.46 is the upstream patch if those features are introduced.

Development-server exposure is separate from the installed release. The candidate changes both development/preview scripts from all interfaces to `127.0.0.1`, so they do not advertise source/preview access on the LAN by default. This does not change the packaged application's server bindings. The review did not scan unrelated running services or claim that the user's machine is free of vulnerabilities.
